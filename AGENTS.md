# AGENTS.md

Single-binary Go **stdio MCP server** (module `screenreader`, code in `server/`) that lets an opencode agent capture and drive a Remote Desktop window on macOS via cgo (robotgo, AppleScript). The agent reads the screen with its **own vision**: `capture` returns a PNG and nothing else.

## Commands (run from `server/`)

```bash
CGO_ENABLED=1 go build -o screenreader .   # output is gitignored
VERSION=v1.2.3 ./release.sh               # signed+notarized dmg in dist/ (Developer ID + notarytool creds; see docs/reference.md "Release builds")
CGO_ENABLED=1 go vet ./...
CGO_ENABLED=1 go test ./...                # full suite (tools/input need cgo to compile)
go test ./internal/geom/ ./internal/config/ ./internal/keycombo/ ./internal/window/ ./internal/camera/  # fast loop, cgo-free
```

- `CGO_ENABLED=0` fails the full build/test: `internal/perms` (and robotgo users) are cgo-only.
- No CI, Makefile, or linter config — gate changes on `go vet` + `go test`; keep code gofmt-clean.

## Layout

- `server/main.go` — registers the 15 MCP tools (three `Register*` funcs in `internal/tools`, the only file touching the MCP SDK). Reading is one tool (`capture`).
- `internal/window` — AppleScript via `osascript` (cgo-free); `internal/capture`, `internal/input` — cgo (robotgo); `internal/sck`, `internal/colist`, `internal/perms` — cgo (Objective-C / CoreGraphics); `internal/geom`, `internal/config`, `internal/keycombo` — pure logic.
- Config lives at `~/.config/screenreader/config.json` and is **re-read on every action** — live edits apply without restarting the server. Per-call args override config.

## Conventions & gotchas

- Coordinates are **screen-absolute, top-left origin, Y down** everywhere. `capture` may downscale or Retina-double the image — always map image→screen via `geom.MapImageToScreen` (pass `img_w`/`img_h`); input tools expose this as `coords: "image"`.
- Reading is vision-only: `capture.max_width` defaults to **0 = native resolution** because the PNG is the model's only reading channel (a negative per-call `max_width` also forces native).
- Two capture paths, chosen by **target kind** (`internal/tools` `classifyTarget` → `wantsWindow`): an **app** target renders that single window through `internal/sck` (ScreenCaptureKit), so overlapping windows are excluded; a pinned **rect** or **screen** target uses the region grab (robotgo → `CGDisplayCreateImageForRect`) and captures the screen **as seen**, overlaps included — that is what those targets mean, never isolate a window for them. `capture.window` is tri-state (`*bool`: absent/`null` = auto as above, `true`/`false` pinned); a per-call `window` arg wins, and an explicit `window: true` on a rect/screen target **errors** rather than downgrading, while a config-level `true` leaves rect/screen targets on the region path. Window capture is **loud on failure** — never a silent fallback to the region grab, or a "clean" image would quietly contain other windows. `source=window id=N occluded=…` / `source=region` in the tool's text line says which produced the image; `bounds` is the window frame in window mode (`ignoreShadowsSingleWindow` keeps the image 1:1 with the frame, so `coords: "image"` still maps).
- `occluded=` names windows stacked above the captured one (input is real cursor events at screen points, so a click on an occluded pixel hits the covering window): `colist.Stack()` returns the raw `kCGWindowListOptionOnScreenOnly` list — documented **front to back**, unfiltered and unreordered, keyed by `kCGWindowNumber`, which is the same CGWindowID SCK reports as `SCWindow.windowID` — and `window.Covering(stack, id)` walks the entries above the target, ignoring slivers under `minCoverFraction` (0.5% of the frame) so the menu bar doesn't make nearly every capture look covered. Best effort: absent when the window is not on that list (minimized, other Space). `colist.List()` cannot answer this — it filters and re-sorts.
- `internal/sck` gotchas: **image orientation — do NOT flip.** Drawing a `CGImage` into a `CGBitmapContext` already yields **top-down** bytes, so the reflex `CGContextTranslateCTM(ctx,0,h); CGContextScaleCTM(ctx,1,-1)` (the fix for reading a CGImage's raw data provider) turns window captures **upside-down**. Both halves were measured: synthetic red-top image (plain draw → row 0 red; flipped → row 0 blue) and the live pair `capture {window:false}` vs `capture {window:true}` of the same window (matched only under a vertical flip, MAD 0.24 vs 178 on a clean strip). `CGContextDrawImage` honours the image's own transform, so a manual flip double-flips.
- `internal/sck` gotchas: `CGWindowListCreateImage` is **obsoleted** in the macOS 15+ SDK (it does not even compile) — ScreenCaptureKit is the only per-window API. The macOS 14-only `SCScreenshotManager` is resolved with `NSClassFromString` behind a local `SRScreenshotManager` protocol instead of weak-linked, because cgo's flag allowlist rejects `-Wl,-weak_framework` (the framework itself exists since 12.3, so a plain `-framework` link still launches on macOS 13, the app's floor). Completion handlers arrive on a **background** queue (verified), so a bounded `dispatch_semaphore` wait is enough — no main-queue pumping, and a wedged capture can't hang the server. `SCStreamConfiguration.width/height` default to **1920x1080 on macOS**, so always pass explicit pixels. Filters are cached per window ID for 30s under one mutex (it also serializes SCK use) and rebuilt once on error. **cgo out-params are load-bearing:** a shim that returns a count without assigning `*out` makes `unsafe.Slice(nil, n)` panic — a Go panic exits 2 with **no `.ips` report**, so the child just vanishes mid-request (that bug killed the live server on the first granted window capture); `Windows()` guards for nil, but assign `*out` in every shim that reports a count/size.
- ScreenCaptureKit TCC is **not** interchangeable with the legacy grant: a process can capture fine via robotgo and still be refused here with `-3801 The user declined TCCs`. `doctor`'s `window_capture:` line probes it directly. Rect/screen targets keep working (region path), but since **app targets use SCK by default**, a missing grant breaks the normal `capture` for them — the error tells the user to pass `window: false`.
- AppleScript in `internal/window`: never name a local `lines` (AppleScript treats it as a built-in text property → error -10006); quote app names with `appleQuote` (double embedded quotes); window titles may contain tabs (parsing takes first + last-4 fields, see `splitWindowLine`). Title filtering is shared by both capture paths through `titleFilter`: regex over the whole list first, then the same string as a **literal** substring — the app stores real titles verbatim and `(EXT)`/`•`/`+` in a title make a regex that cannot match itself. App-name matching bridges process-name vs SCK-localizedName separators (`sublime_text` ↔ `Sublime Text`) via `normApp`, exact `EqualFold` still preferred first.
- Tests are pure logic only (no live screen, no TCC). Real capture/input verification needs Screen Recording, Accessibility, and Automation granted to the **hosting app**, plus a restart of that app after each grant (black capture = missing Screen Recording; silent input = missing Accessibility). `SR_DEBUG=1` dumps every osascript script + output to stderr for window-resolution debugging.
- The Swift menu-bar app is implemented per `docs/superpowers/specs/2026-10-06-screenreader-app-design.md` and `docs/superpowers/plans/2026-10-06-screenreader-app.md`: `app/` is a Swift package (`swift build`/`swift test`), `./build.sh` assembles + signs `app/build/Screen Reader MCP.app` embedding the Go binary and the icon (`app/Resources/AppIcon.icns`, authored from `app/Resources/AppIcon.svg`); the app is named **Screen Reader MCP** (bundle ID stays `dev.chack.screenreader`, executable `Screen Reader MCP`) while the embedded Go binary + MCP server name stay `screenreader`; the app spawns `screenreader --http` (loopback Streamable HTTP on :18427, bearer token in config `http.token`) and owns the TCC grants. The app mutates only `app`/`title`/`mode`/`rect`/`camera`/`http`/`hotkey`/`access` in config.json and preserves the other keys. The status menu toggles `access` in place (**Access: full (switch to read-only)** ⇄ **Access: read-only (switch to full)**, wording + mapping in pure `ScreenReaderKit/AccessToggle.swift`, mirroring Go's `tools.Allow`: only `full`/empty are full, anything else reads as read-only); no restart is needed because the Go side re-checks the mode per call.
- The global **stop hotkey** (config `hotkey`, default `f9`, `"off"` disables it): grammar + kVK table in `ScreenReaderKit/Hotkey.swift` (pure, unit-tested), Carbon registration in `ScreenReader/HotkeyCenter.swift`, click-to-record control in `ScreenReader/HotkeyRecorder.swift` (a **local** event monitor, so no extra grant). Carbon `RegisterEventHotKey` is deprecated but deliberate: `NSEvent.addGlobalMonitorForEvents`/`CGEventTap` both need Accessibility (in practice Input Monitoring), which read-only users lack. Fire → `ServerProcess.stop()` — the single stop choke point, deduped; never hook `killChild()`, which also serves restarts. The Go `Config.Hotkey` field is carried but never read; it exists so `set_target`'s Save cannot erase the app's key. Caveat: a bare F-key is a media key unless "Use F1, F2, … as standard function keys" is on, so the default F9 silently never fires on such Macs.
- Camera target (mode `camera`, app-owned `camera: {id,name}` config key — the Go field exists only so `set_target`'s Save preserves it): `internal/camera` wraps AVFoundation (cached session behind one mutex, 30 s idle teardown via `time.AfterFunc`, bounded waits — same discipline as sck). `capture` returns `image=WxH source=camera device="…"` with **no** bounds; pointer tools (click/move/scroll/drag) error while mode=camera, keyboard tools stay allowed. The system default comes from `defaultDeviceWithDeviceType:…Unspecified` (the macOS 10.15+ type-aware API; the legacy `defaultDeviceWithMediaType:` is superseded and cannot express device types); `.external`/`.continuityCamera` device types need macOS 14 (`ExternalUnknown` on 13). Camera TCC (`NSCameraUsageDescription` in the app's Info.plist — hard requirement, no key = no prompt) rides the app's cert like the other grants; the F9 stop hotkey kills the server, which tears the session down and turns the light off.
- Tools drive the **real cursor** unsandboxed; when testing input, prefer `dry_run: true` and keep the target pinned to the Remote Desktop window.
- The app is signed with the **ScreenReader Dev** self-signed identity (login keychain, cert SHA-1 `b705e67e883aeee9b5866c20188bcd582dcc2d1b`, created 2026-10-07): TCC grants are cert-anchored and **survive rebuilds** — `./build.sh` + relaunch needs no re-grant. If the keychain/key is ever lost, recreate via the openssl `-legacy` recipe in the plan's Task 6, rebuild, and grant once more.
